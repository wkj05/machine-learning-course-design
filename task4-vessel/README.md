# 任务四：医学影像分割（眼底血管提取）

在 DRIVE 眼底图像上做血管的像素级二值分割，提交为 Run-Length Encoding（RLE），评价指标 **Dice 系数**。

| 项目 | 数值 |
|---|---|
| 训练集 | 20 张 565×584 彩色眼底图 + 二值 Mask |
| 测试集 | 20 张 |
| 血管占比 | 原图 8.63% → **512 评测网格上 12.87%** |
| 排行榜最好成绩 | **0.85052** |
| 本机 OOF Dice | **0.8312** |

---

## 一、两个必须先确认的数据约定

### 1. 255 = 血管（不是 0）

竞赛页面写的是「血管区域的像素值置为 0，其他区域为 255」，但这是**反的**：实际标签里只有 0 与 255，**255 才是血管**；官方转换脚本 `segmentation_to_csv.py` 也是以 `image[image > 0]` 收集前景。照页面描述写会让 Dice 直接归零。

### 2. 评测口径比原始标注「粗」

官方转换脚本会先把 Mask 双线性缩放到 512×512 再取「大于 0」，这一步把血管整体膨胀一圈——原图占比 8.63%，映射到 512 网格后变成 **12.87%**。也就是说评分比的是「被膨胀过的血管」。

RLE 约定：**1 基、行优先（C 序）**，连续段写成（起点, 长度）对，空格拼接。

---

## 二、方法

最终方案是**从零训练的 U-Net**，核心决策是**让训练口径等于评测口径**。

- **输入 3 通道**：绿色通道（血管对比度最高）+ 除法式局部对比度增强（`g / box_blur(g,24)` 再拉伸）+ 视野掩膜。
- **训练网格**：直接把图像缩放到 512×512 训练，标签用「缩放到 512 后 > 0」生成，与官方评测逐位一致。
- **网络**：U-Net，5 级编解码，基础通道 32，卷积块为 `3×3 conv + GroupNorm + SiLU` ×2。
- **裁块采样**：随机裁 128×128，其中 60% 以血管像素为中心，缓解 8.6% 的极端类别不平衡。
- **损失**：`0.5 × BCEWithLogits(pos_weight=3.0) + 0.5 × SoftDice`。
- **增强**：翻转、90° 旋转、弹性形变（35%）、gamma/亮度/对比度、通道增益。
- **推理**：4 向翻转 TTA；阈值与最小连通域在 OOF 上搜索，但**必须做留一折检验**（4 折挑参数、第 5 折评估）。

## 三、成绩演进

| 版本 | 配置 | OOF Dice | 排行榜 |
|---|---|---|---|
| v1 | U-Net 5 折，原分辨率训练，无 TTA | 0.8089 | 0.82770 |
| v2 | +10 模型（5 折×2 种子）+ 4 向 TTA + 阈值搜索 | 0.8226 | — |
| v2' | 换成 ConvNeXt-T 预训练编码器 | 0.8247 | 0.84597 |
| v3 | **512 评测网格训练** + 10 模型 | 0.8298 | 0.84983 |
| v4 | + 500 epoch | **0.8312** | **0.85052** |

校准结论：排行榜分数 ≈ 本机 OOF + **2.0** 个百分点（四个样本点：+1.88 / +2.13 / +2.00 / +1.93）。其中约 1 个百分点是结构性的——测试侧是 5 折模型平均，而 OOF 只能用单折模型。

---

## 四、唯一真正有效的改动

**训练口径与评测口径一致**。

改之前：在原始分辨率上用 0/255 标签训练，模型学的是「锐利细血管」，而评分比的是「被膨胀过的血管」，只能靠把阈值压到 **0.12** 去全局补厚度——那是用后处理掩盖训练与评测的口径不一致。

改成 512 网格训练后：

| 指标 | 原分辨率训练 | 512 网格训练 |
|---|---|---|
| 最优阈值 | 0.12（贴下边界） | **0.60（清晰内部峰）** |
| 留一折估计 | 0.8189 | **0.8278** |
| in-sample 乐观量 | +0.30 | **+0.002** |

## 六、关于尾部误差

OOF 的比较分辨率只有约 ±1 个百分点，因为第 12、第 5 两张图在不同折模型下的 Dice 极差达 0.152 与 0.128——它们的「折运气」就足以让整体均值抖动 1 个点。因此任何小于 0.1 个百分点的改进都不可分辨。

这两张图的错误方向还相反（#12 预测面积比 GT 少 33%，#5 多 32%），所以**不存在「整体加粗/变细」的全局修正能同时救它们**，这也解释了为什么阈值曲线是平的、膨胀是灾难。

## 八、复现

```bash
# 本机（RTX 4060 可用，约 30~40 分钟）
python t4_kaggle.py

# Kaggle：把 t4_kaggle.py 整个粘进一个 code cell，GPU T4 x2，
# 并挂载 2026task-4 数据集；预算默认 420 分钟
```
